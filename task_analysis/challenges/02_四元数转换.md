# 挑战 2：四元数与欧拉角的转换

代码定位：[`Project/APP_FUNC/IMU.c`](../../Project/APP_FUNC/IMU.c#L212) 的 `Quat_Init`、四元数积分和 `Angle_t` 输出；[`Project/APP_FUNC/IMU.h`](../../Project/APP_FUNC/IMU.h#L7) 的单位常量。

## 1. 这道题真正要解决什么

在飞控里，姿态既要适合程序连续更新，又要适合人类观察和调参。

- 程序内部更适合维护四元数；
- 串口显示、上位机界面、PID 调试时更常看欧拉角。

因此，这一题的核心不是“背几个转换公式”，而是搞清楚三件事：

1. 四元数为什么能表示旋转；
2. 四元数为什么适合飞控里的姿态积分；
3. 四元数和欧拉角在本项目里如何互相转换。

## 2. 四元数的基础知识

### 2.1 四元数长什么样

四元数一般写成

\[
q = w + xi + yj + zk
\]

也常写成列向量形式

\[
q = [w,\ x,\ y,\ z]^T.
\]

其中：

- `w` 是实部；
- `x, y, z` 是虚部；
- 在本项目代码里，对应 `q0, q1, q2, q3`。

若四元数用于描述姿态，通常要求它是单位四元数，即

\[
\|q\|^2 = w^2 + x^2 + y^2 + z^2 = 1.
\]

只有单位四元数才能对应一个纯旋转。

### 2.2 为什么四元数能表示旋转

若刚体绕单位轴

\[
\mathbf u = [u_x, u_y, u_z]^T
\]

旋转角度 `\alpha`，则对应的单位四元数为

\[
q_{u,\alpha} =
\left(
\cos\frac{\alpha}{2},
u_x\sin\frac{\alpha}{2},
u_y\sin\frac{\alpha}{2},
u_z\sin\frac{\alpha}{2}
\right).
\]

这里最重要的细节是“半角”：

- 物理旋转角是 `\alpha`；
- 写进四元数时要用 `\alpha/2`。

例如，绕 z 轴旋转 `90°` 时，

\[
q =
\left(
\cos45^\circ,\ 0,\ 0,\ \sin45^\circ
\right)
=
\left(
\frac{\sqrt2}{2},\ 0,\ 0,\ \frac{\sqrt2}{2}
\right).
\]

这也是四元数里最常见、最容易记错的一点。

### 2.3 共轭、逆和单位约束

四元数的共轭定义为

\[
q^* = (w,\ -x,\ -y,\ -z).
\]

一般四元数的逆是

\[
q^{-1} = \frac{q^*}{\|q\|^2}.
\]

对单位四元数有

\[
q^{-1} = q^*.
\]

这就是为什么姿态算法每积分一次都要做归一化。若 `|q|` 漂离 1，再拿它去做旋转，得到的就不再是纯旋转。

### 2.4 为什么 `q` 和 `-q` 表示同一个姿态

把 `q` 改成 `-q` 后，四元数的四个分量全部同时变号，但它表示的空间旋转不变。这是因为用四元数转向量时使用的是

\[
p' = q \otimes p \otimes q^{-1},
\]

若把 `q` 和 `q^{-1}` 同时换成 `-q` 和 `-q^{-1}`，两个负号会抵消，最终旋转结果不变。

所以：

- `q` 和 `-q` 是同一个姿态；
- 但若直接画四元数分量曲线，会看到“突然翻号”的现象；
- 做日志记录时，常把当前帧与上一帧的点积保持为正，以维持符号连续。

## 3. 四元数为什么适合飞控

### 3.1 相比欧拉角的优势

欧拉角的优点是直观，但它有两个明显问题：

1. 严重依赖旋转顺序；
2. 会在特定姿态附近出现万向节锁。

四元数避免了这种参数化奇异性，因此更适合做姿态内部状态。

### 3.2 相比旋转矩阵的优势

旋转矩阵有 9 个元素，但姿态本质上只有 3 个自由度。数值积分以后，矩阵还容易慢慢失去正交性，需要额外正交化。

四元数只用 4 个数加 1 个单位约束，就能稳定表示旋转，因此特别适合嵌入式飞控。

### 3.3 在飞控里真正发挥作用的地方

陀螺仪测得的是机体系角速度 `\omega=[g_x,g_y,g_z]`。姿态算法需要把“这一小段时间里又转了多少”持续积累起来。四元数正好适合做这种连续更新：

- 乘法可以表示旋转复合；
- 归一化成本低；
- 与加速度计、磁力计的向量校正兼容。

所以很多 AHRS 算法内部一直维护四元数，而不是直接维护 roll、pitch、yaw。

## 4. 四元数如何作用到向量上

设三维向量

\[
\mathbf v = [v_x, v_y, v_z]^T
\]

先写成纯虚四元数

\[
p = (0, v_x, v_y, v_z).
\]

若姿态四元数为 `q`，则旋转后的向量是

\[
p' = q \otimes p \otimes q^{-1}.
\]

这条式子就是“四元数旋转向量”的根本公式。它表达的是：

- 先按 `q` 代表的姿态做旋转；
- 再用逆旋转封闭乘积；
- 最终得到的新四元数 `p'` 的标量部仍为 0，向量部就是旋转后的三维向量。

也正因为有这条公式，四元数和旋转矩阵本质上是在表达同一件事：坐标系之间的旋转映射。

## 5. 四元数乘法和旋转复合

两个四元数的 Hamilton 乘法为

\[
q_1 \otimes q_2
=
\left(
w_1w_2-\mathbf v_1\cdot \mathbf v_2,\;
w_1\mathbf v_2+w_2\mathbf v_1+\mathbf v_1\times\mathbf v_2
\right).
\]

它最重要的工程意义不是公式本身，而是下面两点：

1. 四元数乘法可表示两个旋转的复合；
2. 四元数乘法一般不满足交换律。

也就是说，通常有

\[
q_1 \otimes q_2 \neq q_2 \otimes q_1.
\]

这和三维旋转“不交换”是同一个几何事实。

因此，代码里若把左乘、右乘，或 `B→N`、`N→B` 的约定弄混，就会出现旋转方向颠倒的问题。

## 6. 角速度为什么能更新四元数

### 6.1 连续时间微分方程

陀螺仪给出的是机体系角速度 `\omega=[g_x,g_y,g_z]`，单位是 `rad/s`。把它写成纯虚四元数

\[
\omega_q = (0,\ g_x,\ g_y,\ g_z),
\]

则常见姿态更新式可写成

\[
\dot q = \frac12 q \otimes \omega_q.
\]

展开后得到

\[
\begin{aligned}
\dot w&=-\tfrac12(xg_x+yg_y+zg_z),\\
\dot x&=\tfrac12(wg_x+yg_z-zg_y),\\
\dot y&=\tfrac12(wg_y-xg_z+zg_x),\\
\dot z&=\tfrac12(wg_z+xg_y-yg_x).
\end{aligned}
\]

这正是本项目 `Attitude_Update` 中积分公式的来源。

### 6.2 离散积分为什么会出现 `halfT`

显式 Euler 积分写成

\[
q_{k+1} = q_k + \dot q \Delta t.
\]

由于微分方程里本来就有一个 `1/2`，因此代码常把

\[
\frac{\Delta t}{2}
\]

记作 `halfT`。本项目里正是这种写法，所以积分行里看起来没有显式 `0.5`，但含义并没有变。

### 6.3 为什么每次都要归一化

积分时会有截断误差和浮点误差，长期运行后会让

\[
\|q\| \neq 1.
\]

因此每次更新后都要做

\[
q \leftarrow \frac{q}{\|q\|}.
\]

不归一化的话，后续由四元数展开出的“旋转矩阵”会逐渐失真。

## 7. 四元数和欧拉角如何互相转换

### 7.1 欧拉角到四元数

若已知某一套固定轴序下的欧拉角 `(roll, pitch, yaw)`，就可以按半角公式组合成四元数。最关键的不是死记某一套写法，而是要先确认：

1. 坐标系定义；
2. 角度正方向；
3. 采用的轴序；
4. 左乘还是右乘约定。

只要其中任意一条不同，转换公式的符号和项次都会变化。

本项目 `Quat_Init` 就是在给定初始姿态假设后，用半角三角函数构造初始四元数。

### 7.2 四元数到欧拉角

四元数内部适合计算，但最终仍常要输出欧拉角给上位机或 PID 接口。项目中的实际代码为

```c
angle.roll  =  asin(2.0f*(q0*q2 - q1*q3))*RAD_TO_ANGLE;
angle.pitch = -atan2(2.0f*(q0*q1 + q2*q3),
                     q0*q0-q1*q1-q2*q2+q3*q3)*RAD_TO_ANGLE;
angle.yaw   =  atan2(2.0f*(q0*q3 + q1*q2),
                     q0*q0+q1*q1-q2*q2-q3*q3)*RAD_TO_ANGLE;
```

这里要特别注意两点：

1. 这些公式是和本项目代码约定绑在一起的，不能直接拿去当作“所有教材里的标准公式”；
2. `asin` 和 `atan2` 的数值边界必须处理，否则浮点误差会放大。

例如 `asin` 的输入理论上应在 `[-1,1]` 内，但实际可能出现 `1.0000001` 这类误差，所以应先夹紧：

```c
float s = 2.0f * (q0*q2 - q1*q3);
if (s > 1.0f) s = 1.0f;
if (s < -1.0f) s = -1.0f;
angle.roll = asinf(s) * RAD_TO_ANGLE;
```

## 8. 本项目实现逐段理解

### 8.1 四元数状态量

`IMU.c` 中的全局姿态状态为

```c
float q0 = 1, q1 = 0, q2 = 0, q3 = 0;
float halfT = 0.0005f;
```

这表示初始姿态默认为单位四元数，也就是“未旋转”状态。

### 8.2 初始化 `Quat_Init`

`Quat_Init` 的作用是构造姿态初值。当前实现本质上是假设初始 roll、pitch 已知或近似为 0，再利用磁力计给出初始 yaw。

这意味着：

- 它可以提供“水平放置启动”时的初始航向；
- 但不能仅靠当前这段代码恢复任意倾斜放置时的完整初始姿态。

若要支持倾斜启动，需要先由加速度估计 roll、pitch，再进行地磁倾斜补偿，最后一起构造四元数。

### 8.3 积分更新

项目里的核心积分代码是

```c
q0 = q0_last + (-q1_last*gx - q2_last*gy - q3_last*gz)*halfT;
q1 = q1_last + ( q0_last*gx + q2_last*gz - q3_last*gy)*halfT;
q2 = q2_last + ( q0_last*gy - q1_last*gz + q3_last*gx)*halfT;
q3 = q3_last + ( q0_last*gz + q1_last*gy - q2_last*gx)*halfT;
```

它正对应上面的微分方程离散化。这里先保存上一拍 `q_last` 再统一更新，是为了避免“同一轮计算里前面的新值污染后面的旧值”。

### 8.4 归一化

项目更新后又执行

```c
norm = invSqrt(q0*q0 + q1*q1 + q2*q2 + q3*q3);
q0 *= norm; q1 *= norm; q2 *= norm; q3 *= norm;
```

这一步不是可有可无的细节，而是维持“四元数仍代表旋转”的必要条件。

### 8.5 最终输出欧拉角

项目没有直接拿欧拉角做积分，而是：

1. 内部持续维护四元数；
2. 最后再由四元数计算 `angle.roll/pitch/yaw`。

这正是飞控里最常见、也最合理的做法。

## 9. 工程上最容易出错的地方

### 9.1 把角速度单位写错

四元数积分要求角速度是 `rad/s`。若把 `deg/s` 或原始 ADC 量直接塞进去，姿态变化速度会整体错掉一个比例。

### 9.2 把 `halfT` 当成完整周期

本项目里 `halfT` 表示 `\Delta t / 2`，不是完整 `\Delta t`。若调用和更新关系没弄清，会导致积分速度缩小或放大一倍。

### 9.3 把项目公式误当成通用公式

四元数转欧拉角、欧拉角转四元数都高度依赖：

- 坐标系；
- 轴序；
- 乘法方向；
- 符号约定。

所以判断公式对不对，不能只看“形式眼熟”，必须拿已知姿态做验证。

### 9.4 只看欧拉角，不看四元数是否归一

有时欧拉角表面上“还能看”，但内部四元数已经偏离单位长度了。此时继续积分，误差会慢慢积累成系统性偏差。

## 10. 一个最值得手算的例子

只绕 z 轴正向旋转 `90°`，则四元数应为

\[
q =
\left(
\cos45^\circ,\ 0,\ 0,\ \sin45^\circ
\right).
\]

代入后可检查三件事：

1. 模长是否等于 1；
2. 用 `q \otimes p \otimes q^{-1}` 旋转单位向量时，方向是否符合预期；
3. 再代入项目中的欧拉角输出公式时，是否只出现一个接近 `90°` 的角。

这个例子可以同时检查：

- 半角有没有写对；
- 乘法顺序有没有写反；
- 坐标轴符号有没有反；
- 输出单位是不是度。

## 11. 这份题目应该掌握到什么程度

学完这一题，至少应该能说清下面几件事：

1. 单位四元数表示旋转；
2. 轴角转四元数必须使用半角；
3. 四元数乘法表示旋转复合，而且一般不交换；
4. 向量旋转用的是 `q \otimes p \otimes q^{-1}`；
5. 陀螺仪角速度可以通过微分方程积分成四元数；
6. 欧拉角只是显示和接口层的表达，内部姿态更适合用四元数维护；
7. 所有转换公式都必须和项目自己的坐标系、轴序、符号约定配套理解。

## 12. 工程结论

对这个项目来说，四元数不是“比欧拉角更高级的另一套角度”，而是更适合程序维护姿态的内部表示。它真正解决的是：

- 如何稳定地把陀螺仪角速度积成姿态；
- 如何避免欧拉角在特定姿态附近的奇异性；
- 如何把地球系参考向量和机体系传感器读数统一到同一套旋转框架里。

而欧拉角的作用，更多是为了输出给人看、给界面显示、给某些控制接口使用。只要把“内部用四元数、外部看欧拉角”这条主线抓住，再去看 `Quat_Init`、积分更新、归一化和 `Angle_t` 输出，整个实现就会清楚很多。
