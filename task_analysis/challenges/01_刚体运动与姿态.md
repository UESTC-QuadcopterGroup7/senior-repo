# 挑战 1：刚体运动及姿态描述

**代码定位：** [`Project/APP_FUNC/IMU.c`](../../Project/APP_FUNC/IMU.c#L251) 的 `Attitude_Update`；[`Project/APP/main.c`](../../Project/APP/main.c#L121) 的 `Task_Angel`；轴向实验记录见 [`docs/九轴数据变化.txt`](../../docs/九轴数据变化.txt)。

## 1. 问题是什么

四轴飞行器可近似为质量和转动惯量固定的刚体。飞控需要回答两个问题：机体在空间中的位置如何变化，以及机体相对于参考坐标系转了多少。位置属于平移运动；本题重点是姿态（orientation）。姿态不能简单用三个独立的“角度寄存器”相加，因为三维旋转不满足交换律：先绕 x 再绕 y，与先绕 y 再绕 x 的结果不同。

仓库把姿态相关的全局量放在 `Project/APP/main.c`：`angle`（输出欧拉角）、`fGyro`（角速度，rad/s）、`acc` 和 `mag`（传感器向量）。`Task_Angel` 每次读取传感器后调用 `Attitude_Update`，因此姿态描述直接位于“传感器坐标 → 旋转状态 → 控制器”的链路中。

## 2. 坐标系、右手定则和状态量

建议明确写下以下约定，并在硬件安装后用实测确认：

| 名称 | 含义 | 仓库线索 |
| --- | --- | --- |
| 机体系 `B` | x 前、y 右、z 方向由右手定则确定 | `docs/九轴数据变化.txt` 记录 x 为 pitch、y 为 roll、z 为 yaw |
| 导航/地理系 `N` | 北、东、地（或北、东、天，必须声明） | `IMU.c` 的注释称“地理坐标系” |
| 角速度 `ωᴮ=[p,q,r]ᵀ` | 在机体系表达的滚转、俯仰、偏航角速度 | `fGyro.x/y/z` |
| 方向余弦矩阵 `R_NB` | 将机体系向量变换到导航系 | 四元数展开式中的 3×3 方向余弦 |

右手定则给出叉乘方向：`a × b` 垂直于二者。姿态误差使用叉乘时，交换两个向量会改变符号，进而改变电机补偿方向。README 中记录的“前倾 pitch 增加、右倾 roll 增加、逆时针 yaw 增加”应作为验收标准，而不是仅依赖注释。

## 3. 欧拉角：定义、矩阵和奇异性

采用 Z-Y-X（yaw–pitch–roll）顺序时，

\[
R_{NB}=R_z(\psi)R_y(\theta)R_x(\phi),
\]

其中 `cφ=cos(φ)`、`sφ=sin(φ)` 等。展开得到

\[
R=\begin{bmatrix}
c_\psi c_\theta & c_\psi s_\theta s_\phi-s_\psi c_\phi & c_\psi s_\theta c_\phi+s_\psi s_\phi\\
s_\psi c_\theta & s_\psi s_\theta s_\phi+c_\psi c_\phi & s_\psi s_\theta c_\phi-c_\psi s_\phi\\
-s_\theta & c_\theta s_\phi & c_\theta c_\phi
\end{bmatrix}.
\]

由旋转矩阵 `R` 反解角度时，`theta = asin(-R31)`，其余两个角用 `atan2`。当 `cos(theta)=0`（俯仰 ±90°）时，滚转和偏航耦合，出现万向节锁；这不是浮点误差，而是参数化本身的自由度丢失。因此仓库只在通信和 PID 接口使用 `Angle_t`，内部保留四元数是合理的。

欧拉角速度与陀螺仪角速度也不是同一个量。Z-Y-X 下有

\[
\begin{bmatrix}p\\q\\r\end{bmatrix}=
\begin{bmatrix}1&0&-\sin\theta\\0&\cos\phi&\sin\phi\cos\theta\\0&-\sin\phi&\cos\phi\cos\theta\end{bmatrix}
\begin{bmatrix}\dot\phi\\\dot\theta\\\dot\psi\end{bmatrix}.
\]

所以不能在大姿态角时直接把 `gyro.x/y/z` 当作 `roll/pitch/yaw` 的导数。

## 4. 轴角法和李群表示

任意非恒等旋转都可表示为绕单位轴 `u` 旋转角度 `α`。令

\[
[\mathbf u]_\times=\begin{bmatrix}0&-u_z&u_y\\u_z&0&-u_x\\-u_y&u_x&0\end{bmatrix},
\quad R=I+\sin\alpha[\mathbf u]_\times+(1-\cos\alpha)[\mathbf u]_\times^2.
\]

小角度时 `R ≈ I + [δθ]×`，这正是误差状态 EKF、梯度姿态校正常用的三维误差向量。矩阵集合 `SO(3)` 是流形，直接对矩阵每个元素做 Euler 积分会破坏正交性；四元数是低成本的替代表示。

## 5. 与 `IMU.c` 的逐段对应

`Project/APP_FUNC/IMU.c` 的 `Attitude_Update` 展开了四元数对应的方向余弦，避免每次构造完整矩阵：

```c
vx = 2 * (q1q3 - q0q2);
vy = 2 * (q0q1 + q2q3);
vz = q0q0 - q1q1 - q2q2 + q3q3;
```

这三个量是“估计的重力单位向量在机体系的分量”。随后 `hx, hy, hz` 把实测磁场旋到参考系，`by/bz` 形成水平和垂直磁场参考，再由 `wx, wy, wz` 旋回机体系。最终：

这里要特别区分矩阵记号：若 `R_NB` 定义为 B→N，那么把导航系重力变到机体系应使用 `R_NBᵀ`；代码中的 `v` 正是在做这个逆向变换。四元数究竟表示 `R_NB` 还是 `R_BN`，仅从 `q0…q3` 的名字无法判断，必须用单位四元数和已知轴旋转验证。文档后续统一把 `v` 称为“机体系预测向量”，避免把符号约定误当成物理事实。

```c
ex = (ay * vz - az * vy) + (my * wz - mz * wy);
ey = (az * vx - ax * vz) + (mz * wx - mx * wz);
ez = (ax * vy - ay * vx) + (mx * wy - my * wx);
```

例如静止且姿态为单位四元数时，`v=(0,0,1)`；若测得加速度方向向右偏，`a×v` 的相应分量就成为角速度修正量。这个叉乘是“几何姿态误差”，不是欧拉角相减。

`main.c` 中的任务调度也属于刚体运动模型的一部分：

```c
GY86_Read(ACC_GYRO_MAG);
Attitude_Update(fGyro.x, fGyro.y, fGyro.z,
               acc.x, acc.y, acc.z, mag.x, mag.y, mag.z);
OSTimeDly(1);
```

实际周期由 RTOS 调度、I²C 阻塞和其他任务共同决定，不能只根据 `OSTimeDly(1)` 宣称严格 1 kHz。

### 一个静止姿态的推导检查

当 `q0=1,q1=q2=q3=0` 时，上述代码给出 `v=(0,0,1)`。如果静止时校准后的加速度也为 `(0,0,1)`，则 `a×v=0`，不会产生重力校正；磁力计只会校正水平航向。若机体向右倾一个小角 `δφ`，测得向量近似为 `(0,-δφ,1)`（符号取决于 z 轴约定），则 `a×v≈(-δφ,0,0)`，`ex` 的正负会直接决定 q 的 roll 修正方向。这个一阶例子可以在桌面上用人为输入测试，不必立即启动电机。

### 旋转向量的组合

两个小旋转 `δθ₁`、`δθ₂` 的组合满足
`δθ₁⊕δθ₂ ≈ δθ₁+δθ₂+1/2(δθ₁×δθ₂)`。第二项说明姿态误差不能简单地按三个角相加，也解释了代码使用叉乘而不是逐轴角度差。对于大机动，应使用四元数乘法或指数映射；对于小误差控制器，三维旋转向量可作为局部坐标。

## 6. 验证方法与常见错误

1. 断开电机，在水平静止时记录 10 s 的 `angle`；均值应稳定，三轴轻推后符号应符合 `docs/九轴数据变化.txt`。
2. 只绕一个轴旋转 ±30°，比较四元数生成的旋转矩阵与实测向量变换。
3. 检查传感器安装方向、PCB 丝印和软件轴交换是否一致；不要通过把 PID 增益改成负数掩盖坐标错误。
4. 给 `Attitude_Update` 增加向量模长为零、NaN 和过大加速度检查，否则 `invSqrt(0)` 会产生无效状态。

另外，源码中 `halfT` 由 `Get_AHRS_Time` 返回，而全局初值是 `0.0005f`；第一次任务调用前若计时器未正确启动，会把默认值误当真实周期。建议在首次有效时间戳到来前冻结姿态更新，并把周期、传感器有效标志一并记录。

结论：欧拉角适合显示和遥控接口，轴角适合解释误差，四元数/旋转矩阵适合内部积分。三者只有在轴序、方向和参考系完全一致时才能互换。

## 7. 从刚体运动学到程序状态更新

为了把“姿态”与传感器读数接起来，先固定一个矩阵约定：令 `R_NB` 把机体系向量变换到导航系，即
`v_N = R_NB v_B`。机体角速度在机体系表达为 `ω_B=[p,q,r]ᵀ`，其反对称矩阵为

\[
[\omega_B]_{\times}=\begin{bmatrix}0&-r&q\\r&0&-p\\-q&p&0\end{bmatrix}.
\]

对固定在机体上的向量求导可得

\[
\dot R_{NB}=R_{NB}[\omega_B]_{\times},\qquad
\dot v_N=R_{NB}(\omega_B\times v_B).
\]

这条式子解释了为什么陀螺仪数据必须是 **rad/s**，也解释了四元数微分式中会出现 `1/2`。如果项目选择的是 `R_BN` 或左乘约定，矩阵乘法顺序和叉乘符号会同时改变；不能只改一行公式。最小的约定测试是给 `ω_B=[0,0,1]`、`dt=0.01`，检查机体 x 轴在导航系中是否朝预期的 y 轴转动。

刚体转动动力学由 Euler 方程给出。若转动惯量在机体系近似对角，代码或仿真中的三个标量方程应写成

\[
\begin{aligned}
I_x\dot p&=\tau_x+(I_y-I_z)qr,\\
I_y\dot q&=\tau_y+(I_z-I_x)rp,\\
I_z\dot r&=\tau_z+(I_x-I_y)pq.
\end{aligned}
\]

交叉项在低速悬停附近通常很小，因此 PID 调试常先使用 `I_x\dot p≈τ_x`；高速翻滚时忽略它会低估耦合，导致“单轴仿真稳定、真实机动振荡”。

## 8. 代码级的坐标和时间检查

`Task_Angel` 在 [`main.c`](../../Project/APP/main.c#L121-L130) 中完成一次采样循环：

```c
GY86_Read(ACC_GYRO_MAG);
if (!Calib_Status()) {
    Attitude_Update(fGyro.x, fGyro.y, fGyro.z,
                    acc.x, acc.y, acc.z,
                    mag.x, mag.y, mag.z);
}
OSTimeDly(1);
```

这里有三个容易混淆的“时间”：传感器内部采样时间、I²C 事务耗时、任务再次获得 CPU 的时间。`OSTimeDly(1)` 在 `OS_TICKS_PER_SEC=1000` 时只表示至少让出 1 ms；真正传给积分器的 `halfT` 由 `TIM2->CNT` 测量。建议把本次快照和 `dt=2*Get_AHRS_Time()` 放在同一个结构体中，再交给姿态算法：

```c
typedef struct {
    Float_t gyro_rad_s;
    Acc_t   acc_raw;
    Mag_t   mag_raw;
    float   dt_s;
    uint32_t sequence;
} ImuSample;
```

这样可以避免 `Task_COM` 在姿态任务更新到一半时读取到“新角速度、旧加速度”的混合状态。若 `dt_s<=0`、超过例如 5 ms，或 I²C 状态为失败，应丢弃本次积分并清除/冻结积分项，而不是把异常时间步乘进四元数。

## 9. 一个可复核的数值例子

取代码输出公式中的纯 roll 状态 `q=(cos15°,0,sin15°,0)`。由 `q0=0.965926`、`q2=0.258819` 得

```text
vx = -2*q0*q2 = -0.500000
vy = 0
vz = q0*q0-q2*q2 = 0.866025
roll = asin(2*q0*q2) = 30°
```

注意这里四元数的物理旋转角是 30°，而示例中写成 15° 的半角；这是检查“半角”和“输出角”是否混淆的好办法。若把测得的归一化加速度设为 `a=(-0.5,0,0.866025)`，则 `a×v=0`，姿态校正项应为零。把 `a.x` 改成 `-0.45` 后，`a×v` 的 y 分量约为 `-0.0433`；其符号应与桌面上实际向右/向左倾斜的修正方向一致。

可在主机上用同一组数字测试叉乘实现，避免一开始就接电机：

```c
static Float_t cross(Float_t a, Float_t b)
{
    Float_t c = {a.y*b.z-a.z*b.y,
                 a.z*b.x-a.x*b.z,
                 a.x*b.y-a.y*b.x};
    return c;
}
```

验收条件应同时包括 `|v|≈1`、`RᵀR≈I` 和轴向符号；只观察最终欧拉角“看起来合理”不足以证明参考系正确。

## 10. 工程结论

姿态表示解决的是几何问题，Euler 方程解决的是动力学问题，PID 解决的是闭环误差问题。三者之间的接口必须写清楚：`fGyro` 为机体系 rad/s，`angle` 为显示/遥控用 degree，`pidRoll/pidPitch` 为 PWM 微秒增量。任何一个接口未标单位，都会把一个合法的数学模型变成方向或增益错误的固件。
